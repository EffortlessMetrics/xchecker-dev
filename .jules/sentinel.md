## 2023-10-27 - Atomic Writes Data Integrity Enhancement
**Vulnerability:** The lockfile code in `crates/xchecker-lock/src/lib.rs` was using `fs::write` to create temporary files prior to an atomic rename. This approach lacked explicit data and metadata synchronization (`fsync`), meaning lockfile updates could be left corrupted or empty if a system crash occurred immediately after the rename.
**Learning:** In Rust, `std::fs::write` does not call `sync_all()`. For proper atomic writes across all platforms, one must open the file explicitly, `write_all`, `sync_all`, `drop` the file handle (vital to prevent "Sharing Violation" errors on Windows during rename), perform the `rename`, and finally open and `sync_all` the parent directory to commit the directory entry.
**Prevention:** Whenever writing critical state files like lockfiles, avoid simple convenience functions (`fs::write`) and instead use robust atomic write patterns with explicit file and directory `sync_all()` calls, ensuring the file handle is dropped before renaming.
