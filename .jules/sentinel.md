## 2024-05-15 - [TOCTOU Vulnerability Mitigation in File Readers]
**Vulnerability:** A Time-of-Check to Time-of-Use (TOCTOU) vulnerability was found in `crates/xchecker-packet/src/builder.rs` where file size was checked using `fs::metadata` before opening the file for reading with `fs::read_to_string`. This allowed concurrent file growth (or swap) between the check and read, potentially causing memory exhaustion and a Denial of Service.
**Learning:** Checking a file's metadata and then separately opening it without maintaining the file descriptor opens a small window for the file to change. While mitigating, `std::io::Read::take(limit).read_to_string(&mut content)` can result in a trait error (`std::io::Take` does not have `read_to_string` directly without explicit scope or via another wrapper). A safer and compiling pattern is `std::io::Read::read_to_string(&mut std::io::Read::take(&mut file, limit), &mut content)`.
**Prevention:** To prevent TOCTOU vulnerabilities when reading files to a limit, always open the file first with `fs::File::open` (gracefully handling directory errors), check the size using `file.metadata()`, and finally read from the file descriptor using a bounded read `std::io::Read::read_to_string(&mut std::io::Read::take(&mut file, limit), &mut content)`.
