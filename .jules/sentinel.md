## 2026-03-28 - [TOCTOU Vulnerability in File Fixup Application]
**Vulnerability:** A Time-of-Check Time-of-Use (TOCTOU) race condition where a file was read with `fs::read_to_string` and then its metadata queried with `fs::metadata`. Between the two system calls, the file could have been replaced, leading to inconsistent application of fixups or security issues if the file permissions/metadata changed.
**Learning:** Reading file content and retrieving metadata sequentially using path-based `std::fs` calls introduces a race condition and is inefficient because the path must be resolved twice by the OS.
**Prevention:** Always open a file handle with `std::fs::File::open`, then extract metadata via `file.metadata()`, and read content using `std::io::Read::read_to_string(&mut file, &mut buf)`. This ensures that both the metadata and the content belong to the exact same file instance. Furthermore, limit reads using `std::io::Read::take(MAX_SIZE)` to prevent memory exhaustion DoS, and never use `metadata.len()` directly as an unbounded allocation or limit parameter.
